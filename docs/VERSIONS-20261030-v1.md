# Version registry

*Last updated 30/10/2026.*

BolexTV ships as **two artifacts that version independently**: a Docker image with the page, and
an APK shell. This file records what is deployed, what each identifier means, and which commit
produced it.

## Two schemes, and why

| | Tuner image | APK |
|---|---|---|
| Identifier | `bolextv-tuner:<YYYYMMDD><a-z>` | `versionName` (semver) + `versionCode` |
| Pace | Changes several times a day | Changes when navigation or lifecycle changes |
| Rollback unit | Container + image ID | `adb install -r` of the previous APK |
| Carries | Practically every user-visible feature | Focus model, key dispatch, exit prompt, WebView lifecycle |

The tuner tag dates the **day** of the build and letters the order within it: `20261030`,
`20261030b`, `20261030c`… The letter is the build order, never a feature promise.

### Recommended convention going forward

- Bump `versionCode` on every installable build, `versionName` on notable behaviour changes.
- Record the pair here in the same commit as the build, alongside the tuner tag that pairs with
  it — a shell bug and a page bug look identical from the sofa, so the pair matters.
